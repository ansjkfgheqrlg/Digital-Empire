# DEC-000 — 7 sezioni canoniche in 1 file per agente

- **Data:** 2026-07-21
- **Contesto:** MBA invariante #5 chiede "7 file canonici per agente" (spec/system-prompt/tools/
  playbook/evals/failure-modes/memory). Con 11 agenti sarebbero 77 file.

## Opzioni
- **A:** 7 file separati per agente (77 file). Massima aderenza formale.
- **B:** 1 file ricco per agente con le 7 **sezioni** dentro (11 file).

## Scelta: **B**
## Motivo
La critica-guida esplicita di master-build-architecture (verbatim dell'utente nel repo) è
*"niente stub, profondità reale, struttura visibile"*. 77 file rischiano decine di stub magri —
esattamente ciò che quel feedback condanna. Un file ricco per agente dà **profondità + navigabilità**
mantenendo tutte e 7 le sezioni tracciabili. La struttura resta visibile (cartelle operatori/
controllo/supporto). Se in futuro serve packaging `npx skills`, si può esplodere in 7 file da qui.

## Conseguenze
- `ARCHITECTURE.md` documenta la mappatura sezione→(ex file).
- Nessuno stub: ogni agente ha contenuto reale in tutte le 7 sezioni.
