# Content-Forge Protocol — source to operating capability

## Pipeline

1. **INGEST INTEGRAL** — acquire original file/link/transcript. For video, extract and read frames.
2. **EVIDENCE LEDGER** — every atom has source + locator + confidence.
3. **ATOMS** — claims, procedures, examples, constraints, failure modes, metrics.
4. **MKD** — expand atoms with Digital Empire application; never make the source poorer.
5. **TARGET CLASSIFICATION**:
   - reference: useful knowledge;
   - rule: stable constraint;
   - workflow: repeatable sequence with I/O/gates;
   - skill: recurring capability with triggers/progressive disclosure/evals;
   - agent/team: persistent owner/coordination need.
6. **PORTFOLIO CHECK** — Chief-Forge searches existing skills/workflows/agents.
7. **ARCHITECTURE** — canonical blueprint and contradiction check.
8. **FORGE** — build inside the blueprint.
9. **EVAL** — happy, edge, failure and live/dry distinction.
10. **REGISTER** — REGISTRO-IMPRESA/skills-map + owner/controller/origin/governance.
11. **MEASURE** — performance and failure data feed the next version.

## Promotion rules

A social pattern becomes a reusable rule only if:

- ≥3 comparable examples;
- source locators exist;
- no contradiction with platform/brand/safety policy;
- observed correlation is not mislabeled causation;
- it produces a clear behavioral delta in a target workflow.

A workflow becomes a skill only if:

- users/tasks trigger it repeatedly;
- a deterministic checklist is insufficient by itself;
- progressive disclosure reduces context cost;
- tests can determine success/failure;
- there is an owner and update path.

## Video anti-fake gate

FAIL if any is true:

- only title/thumbnail read;
- transcript summarized without full read;
- no frames read;
- pattern has no timestamp/frame reference;
- competitor asset is copied rather than transformed;
- “performance” claimed without metrics.
