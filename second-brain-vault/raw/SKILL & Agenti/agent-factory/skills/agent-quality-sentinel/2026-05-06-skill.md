# Agent Quality Sentinel

This is the fourth and final skill in the agent-factory pipeline. It conducts a comprehensive audit of all agent files and produces a prioritized report with specific fixes.

The Sentinel does not say "this could be better." It says "line 12 of your system prompt has no process steps — replace it with X."

## The Audit Process

### Phase 1: Structural Audit

Check every file for structural validity. Consult `references/quality-checklist.md` for the complete rubric.

**For each agent `.md` file, verify:**

```
FRONTMATTER AUDIT
-----------------
[ ] name: valid format (lowercase, hyphens, 3-50 chars, starts/ends alphanumeric)
[ ] description: present, length 200-2000 chars
[ ] description: starts with "Use this agent when..."
[ ] description: contains 2+ <example> blocks
[ ] Each example: has Context, user, assistant, commentary
[ ] model: one of inherit/opus/sonnet/haiku
[ ] color: one of blue/cyan/green/yellow/magenta/red
[ ] tools: if present, contains only valid tool names

SYSTEM PROMPT AUDIT
-------------------
[ ] Starts with "You are..." (second person, present tense)
[ ] Contains identity/role definition
[ ] Contains mission statement
[ ] Contains core responsibilities (3-6 items)
[ ] Contains operating process (step-by-step)
[ ] Contains output contract (explicit format)
[ ] Contains quality standards or self-check
[ ] Contains hard constraints (Never/Always)
[ ] Contains edge case handling
[ ] Length: 300-3000 words (below 300 = too thin, above 5000 = bloated)
```

**For `plugin.json`:**
```
[ ] Valid JSON
[ ] name field present
[ ] version field present
[ ] description field present
```

### Phase 2: Quality Audit

Go beyond structural validity to evaluate actual quality.

**Triggering Quality Score (TQS):**

Rate the description's triggering reliability 1-10:

| Score | Meaning |
|---|---|
| 1-3 | Vague, will never trigger reliably |
| 4-6 | Triggers on obvious cases, misses edge cases |
| 7-8 | Good triggering, minor improvements possible |
| 9-10 | Excellent — precise, specific, covers edge cases |

For any score below 8: provide a rewritten description.

**System Prompt Depth Score (SPDS):**

Rate the system prompt quality 1-10 across 5 dimensions:

| Dimension | What it measures |
|---|---|
| Identity Clarity | How specific and expert-level the persona is |
| Process Completeness | Are all steps defined? Is there reasoning for each step? |
| Output Precision | Is the output format exact and unambiguous? |
| Constraint Adequacy | Are hard limits and edge cases covered? |
| Model Alignment | Does the prompt style match the assigned model? |

For any dimension below 7: provide specific improvements.

**Architecture Coherence Check (ACC):**

Evaluate the agent system as a whole:

- [ ] Every agent has exactly ONE primary responsibility
- [ ] Orchestrator(s) don't do specialist work
- [ ] No duplicate responsibilities across agents
- [ ] Data flow is logical and complete
- [ ] No orphan agents (agents with no clear input source)
- [ ] No missing agents (gaps in the workflow)
- [ ] Model assignments are optimal (not all opus, not all haiku)
- [ ] Tool assignments follow least-privilege

### Phase 3: Simulation Test

For each agent, run a mental simulation:

1. **Happy path:** Give the agent its ideal input. Does the system prompt produce the expected output?
2. **Edge case:** Give the agent malformed, empty, or unexpected input. Does it handle gracefully?
3. **Failure mode:** What breaks if [most likely failure] occurs? Is there a recovery path?

Document any simulation failures as Priority 1 issues.

### Phase 4: Produce the Audit Report

Format the report as follows:

```markdown
# Agent Quality Audit Report
Date: [date]
Plugin: [plugin-name]
Total Agents: [N]
Overall Score: [X/10]

---

## CRITICAL ISSUES (fix before installing)
[List issues that will cause agent failure or non-triggering]

Issue #1: [agent-name] — [problem]
Fix: [exact text to write/change]

---

## MAJOR ISSUES (fix for production quality)
[Issues that cause inconsistent behavior or poor output]

Issue #2: [agent-name] — [problem]
Fix: [exact text to write/change]

---

## MINOR IMPROVEMENTS (optional polish)
[Issues that reduce quality but won't break functionality]

---

## AGENT SCORES

| Agent | TQS | SPDS | ACC | Overall |
|---|---|---|---|---|
| [name] | X/10 | X/10 | Pass/Fail | X/10 |

---

## REWRITTEN COMPONENTS
[For any TQS < 8 or SPDS dimension < 7, provide the complete rewritten version]

### [agent-name] — Rewritten Description:
[full new description]

### [agent-name] — Rewritten System Prompt Section [section-name]:
[full rewrite]

---

## INSTALLATION CLEARANCE
[ ] Cleared for installation — all critical issues resolved
[ ] NOT cleared — [N] critical issues remain
```

### Phase 5: Self-Healing Mode

If the user wants the Sentinel to fix issues automatically (not just report them):

1. Read each issue from the audit report
2. Apply the fix directly to the agent file
3. Re-run the relevant audit check to confirm fix worked
4. Update the issue status to RESOLVED
5. Produce a summary of all changes made

To activate: "Fix all the issues automatically" or "apply all fixes."

### Phase 6: Final Clearance

After all critical issues are resolved, issue the final clearance:

> "All critical issues resolved. Plugin is cleared for installation. Triggering Quality Score: [X]/10. System Prompt Depth Score: [X]/10. Architecture: Coherent.
>
> Install with: `/plugin install [path]` or copy to `~/.claude/plugins/[plugin-name]/`"

## Quick Reference: Most Common Issues

**Issue 1: Weak description** (causes agent to never trigger)
- Symptom: Description says "helps with X" without specific phrases
- Fix: Rewrite with "Use this agent when..." + specific trigger phrases + 2 examples

**Issue 2: Thin system prompt** (causes inconsistent behavior)
- Symptom: System prompt is under 300 words, no process section
- Fix: Add operating process (step-by-step), output contract, constraints

**Issue 3: Wrong model choice**
- Symptom: haiku used for complex reasoning, opus used for simple formatting
- Fix: Reassign — opus for judgment/strategy, haiku for parsing/routing

**Issue 4: Missing output contract**
- Symptom: System prompt says "produce a good analysis" with no format
- Fix: Add explicit output format template with field names

**Issue 5: Overpowered tools**
- Symptom: Read-only agent has Bash and Write access
- Fix: Restrict to minimum needed tools

**Issue 6: All-purpose orchestrator**
- Symptom: Orchestrator description includes specialist tasks
- Fix: Strip all specialist work from orchestrator, create dedicated specialists
