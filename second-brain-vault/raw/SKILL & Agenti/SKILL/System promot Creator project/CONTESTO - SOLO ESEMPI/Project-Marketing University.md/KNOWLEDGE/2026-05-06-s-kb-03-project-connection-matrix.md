## 4.1 — Come Collegare un Framework a un Progetto

Quando esegui il Workflow W1 (Step 6) o quando l'utente chiede
di collegare un concetto, segui questa procedura:
STEP 1: IDENTIFICA L'AREA DEL FRAMEWORK
│ Il framework è stato classificato in quale area/sottoarea?
│ (dal campo ③ della Scheda Framework)
│
STEP 2: CONSULTA LA MATRICE (Sezione 2)
│ Cerca la riga corrispondente nella matrice della Sezione 2
│ Identifica:
│ - Progetto primario
│ - Fase primaria
│ - Progetti secondari
│ - Trigger
│
STEP 3: VERIFICA PERTINENZA
│ Il collegamento suggerito dalla matrice ha senso per
│ QUESTO framework specifico?
│ - SE SÌ → Usa il collegamento della matrice
│ - SE NO → Override manuale (vedi Sezione 4.2)
│
STEP 4: DEFINISCI IL TRIGGER
│ In quale SITUAZIONE SPECIFICA l'utente dovrebbe usare
│ questo framework nel progetto?
│ Il trigger deve essere una situazione concreta e riconoscibile.
│ Esempi di trigger buoni:
│ - "Quando scrivi la headline di una sales page per un cliente"
│ - "Quando prepari la strategy call con un prospect"
│ - "Quando analizzi il funnel di un nuovo cliente"
│ Esempi di trigger cattivi:
│ - "Quando serve" (troppo vago)
│ - "Sempre" (non è un trigger)
│ - "Nel marketing" (troppo ampio)
│
STEP 5: COMPILA IL CAMPO ⑦ DELLA SCHEDA
│ Progetto primario: [emoji + nome]
│ Fase specifica: [fase del progetto]
│ Situazione trigger: [quando usare]
│ Progetti secondari: [se applicabile]

text


## 4.2 — Override Manuale della Matrice
SE il collegamento suggerito dalla matrice NON è pertinente
per il framework specifico:

CASO 1: Il framework si applica a un progetto diverso da quello
suggerito dalla matrice
→ Usa il progetto corretto e segnala nella scheda:
"Collegamento override: la matrice suggerisce [X] ma questo
framework si applica meglio a [Y] perché [motivo]"

CASO 2: Il framework si applica a una fase diversa da quella
suggerita dalla matrice
→ Usa la fase corretta e segnala

CASO 3: Il framework è veramente trasversale (applicabile a tutti
i progetti senza un primario chiaro)
→ Progetto primario: 🧠 Strategy Command Center (Area 3: Decisioni)
→ Progetti secondari: tutti quelli rilevanti
→ Trigger: "Quando [situazione specifica] in qualsiasi progetto"
→ Segnala: "Framework trasversale — applicabile a tutti i progetti"

CASO 4: Il framework non si applica a NESSUN progetto attivo
→ Questo NON dovrebbe succedere (violazione criterio 4 di estraibilità)
→ Verifica se il framework andava estratto
→ SE il framework è valido ma non collegabile ora:
segnala come "Framework in attesa — collegabile quando [condizione]"

text


## 4.3 — Framework con Multipli Progetti
SE un framework si applica FORTEMENTE a più di un progetto
(non solo secondario ma primario in multipli contesti):

→ Compila il campo ⑦ con TUTTI i progetti:
Progetto primario: [il progetto dove l'impatto è maggiore ORA]
Progetti secondari: [tutti gli altri]

→ Nell'azione entro 7 giorni (campo ⑧):
scegli UN SOLO progetto per l'azione immediata
(quello dove il bisogno è più urgente ORA)

→ Nella nota: "Applicabile anche a [progetto Y] nella fase [Z].
Dopo l'applicazione in [progetto X], considerare applicazione
anche in [progetto Y]."

aumentano l'open rate". L'AI ha estratto il framework "Subject Line
Power Formula" e lo ha classificato in AREA_2 → 2C → 2C.01.

1. Consulto Sezione 2 → AREA 2, Sottoarea 2C:
   - Progetto primario: ⚡ Agency (Fase 5 — copy email per cliente)
   - Progetti secondari: 🎥 YouTube (Fase 6 — email nurture)

2. Verifico pertinenza: SÌ, il framework è applicabile al delivery email

Progetto primario: ⚡ Agency Operations

per un cliente o per la newsletter propria

# ⚠️ NOTE E AVVERTENZE
# ──────────────────────────────────────────────────────

1. **La matrice è una GUIDA, non una legge.** Il collegamento automatico
è corretto nel 90% dei casi. Nel 10% restante, usa l'override manuale
(Sezione 4.2) e segnalalo.

2. **I progetti possono EVOLVERE.** Se l'utente aggiunge nuovi progetti
o modifica le fasi di quelli esistenti, la matrice va aggiornata.
Segnala se noti che le fasi descritte qui non corrispondono più alla
realtà del progetto.

3. **La matrice inversa (Sezione 3) è il punto di partenza per il
Workflow W3 (Suggerimento Studio).** Quando l'utente chiede cosa
studiare, SEMPRE partire dal problema nel progetto, MAI da
"cosa sarebbe interessante studiare".

4. **Un framework SENZA collegamento è un framework INCOMPLETO.**
Il campo ⑦ della Scheda non può mai essere vuoto. Se il collegamento
non è chiaro, chiedi all'utente.

5. **Priorità impatto (Sezione 5) guida l'ordine delle azioni.**
Quando l'utente ha più framework da applicare, suggerisci SEMPRE
di iniziare da quelli con impatto ALTISSIMA o ALTA.
