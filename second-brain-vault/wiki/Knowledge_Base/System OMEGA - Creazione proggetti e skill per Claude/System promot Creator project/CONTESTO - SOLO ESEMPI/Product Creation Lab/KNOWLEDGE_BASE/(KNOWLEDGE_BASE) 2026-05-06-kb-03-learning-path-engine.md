# 📋 COME UTILIZZARE QUESTO FILE
# ──────────────────────────────────────────────────────

Questo file contiene il sistema completo per progettare la struttura del prodotto:
il learning path (PRIMA→DOPO) e l'outline dettagliato per ogni modulo.

Usalo negli Step 1.2 e 1.3 della pipeline, DOPO aver completato la ricerca (KB_02).

**Obiettivo**: Trasformare i risultati della ricerca in una struttura formativa
che porta lo studente da uno stato preciso a un altro stato preciso,
attraverso trasformazioni intermedie verificabili.


# ──────────────────────────────────────────────────────
# 🎯 STEP 1.2 — LEARNING PATH PRIMA→DOPO
# ──────────────────────────────────────────────────────

Il learning path risponde a questa domanda:
"Qual è il viaggio completo che fa lo studente comprando questo prodotto?"

Non è un sommario. Non è una lista di argomenti.
È la mappa di trasformazione da uno stato di partenza a uno stato di arrivo.

## Regola Fondamentale del Learning Path

Ogni prodotto formativo porta lo studente da uno STATO PRIMA a uno STATO DOPO.
Se non riesci a definire chiaramente questi due stati → il prodotto non è pronto per la produzione.

---

## TEMPLATE LEARNING PATH — STATO PRIMA

```
STATO PRIMA (lo studente arriva così):
├── Non sa: [cosa non sa — elenco 3-5 punti specifici]
├── Non ha: [cosa non ha — tool, template, framework, sistema]
├── Si sente: [come si sente — 2-3 emozioni concrete]
└── Il suo problema quotidiano:
    "[Descrizione in 2-3 righe del problema come lo vive ogni giorno]"
```

### Esempio compilato (corso "Sistema di Acquisizione Clienti Freelance"):

```
STATO PRIMA:
├── Non sa: identificare quali clienti ha senso contattare; come scrivere un
│          outreach che riceve risposta; come qualificare un lead in 5 minuti;
│          come presentare il proprio valore senza sembrare disperato;
│          come followuppare senza essere fastidioso
├── Non ha: sistema per trovare prospect; template di outreach testati;
│          script per la prima call; CRM anche solo semplice; processo
│          di followup strutturato
├── Si sente: frustrato quando manda email e non riceve risposta;
│            insicuro quando deve spiegare quanto vale il suo lavoro;
│            invischiato nell'alternanza boom/bust (o troppo lavoro o niente)
└── Problema quotidiano: "Finisce il progetto con un cliente, si trova senza
    pipeline. Ricomincia ogni volta da zero: posta su LinkedIn, manda due email,
    aspetta. Se arriva qualcosa, bene. Se no, abbassa il prezzo. Non ha un sistema."
```

## TEMPLATE LEARNING PATH — STATO DOPO

```
STATO DOPO (lo studente esce così):
├── Sa: [cosa sa fare — elenco 3-5 azioni concrete e misurabili]
├── Ha: [cosa ha — tool, template, framework, sistema concreto]
├── Si sente: [come si sente — 2-3 emozioni concrete]
└── La sua nuova realtà quotidiana:
    "[Descrizione in 2-3 righe di come lavora adesso]"
```

### Esempio compilato (stesso corso):

```
STATO DOPO:
├── Sa: costruire una lista di 20 prospect qualificati in 2 ore; scrivere
│       outreach personalizzato che riceve risposta nel 20-30% dei casi;
│       qualificare un lead in 5 domande; presentare il valore senza scuse;
│       costruire e gestire una pipeline con followup automatico
├── Ha: sistema di ricerca prospect (3 fonti); 3 template di outreach
│       adattabili; script per la prima call; CRM in Notion; sequenza
│       di followup a 4 step
├── Si sente: in controllo della propria pipeline; sicuro quando negozia
│            il prezzo; tranquillo anche nelle fasi di transizione
└── Nuova realtà quotidiana: "Ogni lunedì passa 30 minuti a controllare
    la pipeline. Sa esattamente quanti prospect ha in ogni fase. Non aspetta
    che i clienti arrivino — sa come andare a trovarli. La lista è sempre
    aggiornata. Il prossimo contratto è sempre visibile."
```

## TEMPLATE LEARNING PATH — IL PERCORSO (TRASFORMAZIONI INTERMEDIE)

Il percorso è una sequenza di trasformazioni intermedie.
Ogni modulo = 1 trasformazione intermedia.

L'ordine è obbligatoriamente sequenziale: il modulo 3 presuppone il 2, il 2 presuppone l'1.

```
┌─────────┬──────────────────────────────┬──────────────────────────────┐
│ Modulo  │ Trasformazione               │ Lo studente dopo questo      │
│         │ (Da → A)                     │ modulo può...                │
├─────────┼──────────────────────────────┼──────────────────────────────┤
│ Mod. 1  │ Da "non so chi contattare"   │ Costruire una lista di 20    │
│         │ a "ho un sistema per         │ prospect qualificati con 3   │
│         │ trovare prospect"            │ fonti specifiche             │
├─────────┼──────────────────────────────┼──────────────────────────────┤
│ Mod. 2  │ Da "mando email che          │ Scrivere outreach che riceve │
│         │ nessuno apre" a "ho          │ risposta nel 20-30% dei casi │
│         │ template che funzionano"     │ usando 3 template testati    │
├─────────┼──────────────────────────────┼──────────────────────────────┤
│ Mod. 3  │ Da "non so come gestire      │ Qualificare un lead in 5     │
│         │ la prima call" a "ho         │ domande e decidere se        │
│         │ uno script preciso"          │ procedere o no               │
├─────────┼──────────────────────────────┼──────────────────────────────┤
│ Mod. 4  │ Da "abbasso il prezzo        │ Presentare il proprio valore │
│         │ appena il cliente            │ con il framework Price-Value │
│         │ esita" a "so difendere       │ senza sentirsi in colpa      │
│         │ il mio valore"              │                              │
├─────────┼──────────────────────────────┼──────────────────────────────┤
│ Mod. 5  │ Da "non ho un sistema        │ Gestire una pipeline attiva  │
│         │ di followup" a "la           │ con la sequenza 4-step       │
│         │ pipeline è sempre attiva"   │ e il CRM Notion              │
└─────────┴──────────────────────────────┴──────────────────────────────┘
```

### Regole del Learning Path:

1. **Ogni modulo ha UNA trasformazione** — non "modulo sul marketing digitale" ma "da 0 follower a primo post virale"
2. **L'ordine è sequenziale** — il modulo 3 richiede il 2. Se può essere saltato → non è un modulo, è un bonus
3. **Nessun modulo è "teoria pura"** — ogni modulo ha un output pratico che lo studente produce
4. **Massimo 7 moduli** (5 è ideale) — oltre 7, stai costruendo 2 corsi diversi
5. **Lo studente può rispondere dopo ogni modulo**: "Cos'ho imparato? Cos'ho prodotto? Come lo uso domani?"

│   ├── La differenza tra lead e prospect: un lead è chiunque mostri interesse,

│     rendono più di 200 non qualificati. Il tuo tempo è il vincolo.

├── Output pratico: Lo studente ha la sua lista prospect con almeno 10 nomi compilati

# 📏 REGOLE STRUTTURALI DELL'OUTLINE

## Struttura ottimale delle lezioni per modulo

Ogni modulo dovrebbe avere 3 lezioni che seguono questo pattern:

| Lezione | Tipo | Obiettivo | Output studente |
|---|---|---|---|
| Lezione N.1 | Concetto chiave | "Capisce PERCHÉ" | Ha il "frame mentale" corretto |
| Lezione N.2 | Framework/Sistema | "Sa COME" | Ha il sistema/framework da usare |
| Lezione N.3 | Applicazione pratica | "Fa ADESSO" | Produce un output concreto |

Variazione accettata: 2-4 lezioni per modulo (non meno di 2, non più di 4 in genere).

## Regole per i titoli delle lezioni

- Usa verbi d'azione o risultati: "Costruisci la lista", "Il Sistema 3F", "Identifica il tuo ICP"
- Evita titoli generici: NON "Introduzione", "Overview", "Concetti base"
- Ogni titolo deve suggerire cosa lo studente sa fare dopo: "Come scrivere la prima email → saprai come"

## Regole per le trasformazioni di modulo

Formato obbligatorio: `Da: "[stato specifico]" → A: "[stato specifico e misurabile]"`

Esempi corretti:
- "Da: non sa come rispondere alle obiezioni → A: usa 5 pattern specifici per qualsiasi obiezione"
- "Da: non ha sistema di follow-up → A: gestisce pipeline con sequenza 4-step in Notion"

Esempi sbagliati (troppo vaghi):
- "Da: non sa fare X → A: sa fare X" (non specifica)
- "Da: scarso → A: bravo" (non misurabile)
- "Da: zero esperienza → A: esperto" (non credibile per un solo modulo)

## Checkpoint — Come scriverlo bene

Le domande del checkpoint devono essere verificabili dallo studente stesso.
Non "Ho capito il concetto?" (soggettivo) ma "Ho il template compilato con 20 nomi?" (verificabile).

Ogni checkpoint deve avere almeno una domanda su:
1. Conoscenza acquisita (so cosa è / so come funziona)
2. Tool/template in mano (ho lo strumento)
3. Output prodotto (ho fatto l'esercizio)
4. Prontezza per il modulo successivo (sono pronto a procedere)

# ⚠️ EDGE CASE E GESTIONE ERRORI
# ──────────────────────────────────────────────────────

## Non riesco a definire la trasformazione per un modulo

**Situazione**: "Voglio un modulo su come usare i social media per trovare clienti" — non emerge una trasformazione chiara.
**Soluzione**: Chiedi "Cosa NON sa fare lo studente PRIMA di questo modulo, e cosa sa fare DOPO?" Se la risposta è "impara i social media" non è abbastanza specifica. Forza la specificità: "Prima: non sa quali piattaforme usa il suo target. Dopo: ha identificato le 2 piattaforme giuste e conosce la frequenza e il tipo di post che convertono in quel contesto." Questo è un modulo definito.

## Il learning path ha un "buco" logico tra moduli

**Situazione**: Il modulo 3 presuppone che lo studente sappia fare qualcosa che non è stato insegnato nel modulo 2.
**Soluzione**: Ci sono 3 opzioni: 1) Aggiungi una lezione al modulo 2 che copre quel prerequisito; 2) Sposta il contenuto del modulo 3 a dopo il prerequisito; 3) Esplicita il prerequisito nella descrizione del modulo 3 e indica dove trovarlo (se è un prerequisito "esterno" al corso).

## Il learning path è troppo breve (2-3 moduli)

**Situazione**: Non riesco a strutturare più di 3 moduli per questo prodotto.
**Soluzione**: Potrebbe essere un mini-corso o un PDF, non un corso completo. Verifica: la trasformazione totale (PRIMA→DOPO) è abbastanza grande da giustificare un corso? Se no → riduci il formato e il prezzo in accordo con `KB_07_STANDARD_PER_TIPO.md`.

## Il learning path ha troppe trasformazioni (8-10 moduli)

**Situazione**: Vedo 9 trasformazioni distinte che lo studente deve fare.
**Soluzione**: Hai 2 corsi, non 1. Dividi: identifica le prime 5 trasformazioni che portano a un risultato intermedio vendibile (es: "da zero a prima vendita"). Quelle diventano il Corso Base. Le rimanenti 4-5 diventano il Corso Avanzato (upsell). Torna a P7 Info-Business HQ per validare questa divisione.

## Non so quale ordine usare per i moduli

**Situazione**: Ho 5 trasformazioni ma non capisco quale deve essere prima.
**Soluzione**: Applica la regola della dipendenza: "Il modulo X può essere eseguito senza sapere il contenuto del modulo Y?" Se sì → Y non deve essere prima di X. Se no → Y deve essere prima di X. Costruisci il grafo delle dipendenze e l'ordine emerge naturalmente.
