# Concept: Google Docs come Sistema Operativo del Copywriter

## Overview
Il documento di copy non è solo il contenitore del testo: è un deliverable con la sua UX (per chi lo legge/revisiona) e un sistema di produttività (per chi lo scrive/gestisce). Andrei Pascu (copywriter dal 2021, cliente-facing) usa 8 funzioni native di Google Docs per trasformare un documento grezzo in uno strumento professionale — zero tool esterni, zero costo.

Principio guida: "lo uso sempre, non per comodità mia ma per comodità degli altri — quando qualcuno entra sul documento voglio che abbia l'esperienza più smooth possibile." [Ahp_6rHSOsU#00:08:43]

## I 3 Livelli del Sistema

### 1. Pulizia del formato (il documento non è carta)
Un copy per una Sales page "non verrà mai stampato, quindi l'impaginazione a pagine diventa solamente fastidiosa perché divide i testi a metà". Azione: File → Impostazione pagina → Senza pagine, impostato come default. Il documento diventa un flusso continuo, coerente con il suo uso reale (schermo, non stampa).

### 2. Struttura navigabile (il documento non è un blocco unico)
Usare gli **heading predefiniti** (mai bold+size manuale — "è veramente una cosa da nabbi") genera automaticamente un **outline navigabile** nel pannello sinistro. Beneficio duplice: estetica/velocità + capacità di saltare tra sezioni con un click in documenti lunghi. Per aggiornare lo stile di TUTTE le intestazioni insieme: formatta un'istanza → Stili → "Aggiorna [stile] perché corrisponda".

### 3. Metadati di stato e navigazione (il documento non è statico)
- **Note colorate**: testo giallo = nota operativa separata dal copy (es. "[inserire logo]"), reso ripetibile trasformandolo in un heading dedicato.
- **Dropdown di stato**: badge inline per sezione (Da iniziare / In corso / In revisione / Approvato) → il documento diventa un mini-kanban, elimina l'ambiguità su cosa è pronto.
- **Segnalibri + link**: navigazione istantanea a sezioni specifiche via link cliccabile, utile in indici e cross-reference interne.
- **Conteggio caratteri live**: vincolo di piattaforma (headline, oggetto email, titolo) verificabile in tempo reale, anche su una singola selezione.

## Sistema Cartelle Clienti (livello Drive, non Docs)

```
Drive
└── Clienti/
    └── <Nome Cliente>/          (es. "Marco Sfera", "Marco Aurelio")
        ├── visibile al cliente/
        └── NON visibile al cliente/   ← colorata di ROSSO come warning
```

Regola: creare SEMPRE il documento da dentro la cartella Drive corretta, mai da Google Docs diretto — altrimenti tutti i file finiscono in un unico posto indifferenziato e "una volta che ne hai 20, 30, 40 diventano tantissimi, per trovarne uno devi scavare".

## Perché conta per un'agenzia (applicazione DE)

| Problema comune | Soluzione da questo sistema |
|---|---|
| Il cliente riceve un copy disordinato, poco professionale | No-pagine + heading + outline = percezione di cura fin dal primo file inviato |
| Note interne finiscono nel copy finale per errore | Convenzione testo giallo = nota, mai confuso col copy consegnabile |
| Nessuno sa a che punto è un copy lungo/collaborativo | Dropdown di stato per sezione = stato visibile senza chiedere |
| Rischio di condividere per errore materiale riservato | Split cartella visibile/non-visibile per cliente, non-visibile marcata rossa |
| Headline/oggetti sforano il limite della piattaforma | Conteggio caratteri live sulla selezione, non a fine scrittura |

## Anti-pattern esplicito

Formattare i titoli a mano (ingrandire+bold, poi ricopiare/rimodificare ogni volta) invece di usare gli stili: "un pessimo modo di lavorare, anche svantaggioso" — costa tempo ripetuto e non produce struttura navigabile né possibilità di aggiornamento in blocco.
