## CONSIGLI

1. **Cosa migliorare in DE**: applicare alle skill DE lo stesso trattamento "Level 3 — skill tree" mostrato nel video (frame-267): per le 115 `SKILL.md` sopra le 150 righe (a partire dai 5 casi più gravi: `cro-youtube-lead-magnet` 5160 righe, `cro-call` 5146, `cro-strategy-social-(ig-tiktok)` 3942, `printing-press` 3639, `cro-funnel-architect.md` 2771), spezzarle in un router breve (trigger + tabella "quale file per quale job") più file dedicati in `references/`. Questo è un gap reale, misurato, non inventato.

2. **Quale skill nuova**: nessuna skill nuova dedicata è necessaria — la skill `skill-creator` (già presente e usata nella lista skill di DE) è lo strumento corretto per eseguire il refactoring del punto 1. Non c'è gap che giustifichi una skill nuova qui.

3. **Quale agente nuovo**: nessun gap reale che giustifichi un nuovo agente. Il lavoro di refactoring del punto 1 è un task singolo di manutenzione, eseguibile da `chief-forge` (già proprietario della factory di skill/agenti in DE) o da `skill-creator` stesso — non serve un nuovo ruolo permanente.

4. **Quale workflow nuovo**: manca in DE un equivalente della funzione nativa "Routines" di Claude Code (frame-480) applicata in modo sistematico — DE ha scheduler Python sparsi (`EmpireDesk/modules/scheduler.py`, `Workflow pubblicazione automatica/setup_scheduler.py`) ma non un inventario unico delle automazioni schedulate con lo stesso pattern "descrizione + status + repeats + istruzioni" mostrato in frame-456. Consiglio concreto: creare un unico file `company/Memory/ROUTINES.md` che elenchi ogni automazione schedulata esistente in DE con lo stesso formato (nome, cosa fa, quando, dove, cosa NON deve fare) — non serve un nuovo software, serve un indice come quello del video.

5. **Quale esistente potenziare, con quale pezzo preciso**: potenziare il root `CLAUDE.md` di Digital Empire aggiungendo la regola esplicita presa dal prompt "Memory Level 2" del video (frame-406): *"quando un file si sposta o parte un nuovo progetto, aggiorna il router nello stesso turno — un puntatore vecchio è peggio di nessun puntatore."* Questa singola frase, aggiunta come regola operativa a `CLAUDE.md` (già strutturalmente un router valido), chiuderebbe l'unico vero gap procedurale rilevato nel pattern Memory, che per il resto DE rispetta già.
