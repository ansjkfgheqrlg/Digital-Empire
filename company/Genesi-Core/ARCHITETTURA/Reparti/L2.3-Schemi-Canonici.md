# L2.3 — SCHEMI CANONICI
## Organo: ARCHITETTURA (Genesi Core)

## Missione
Custodisce e versiona gli **schemi-template** delle 9 forme che ARCHITETTURA progetta — la
"costituzione delle strutture" della holding. Ogni design parte da uno schema caricato da qui.
Confine netto: L2.3 possiede i *template* (la forma vuota al millimetro), NON le istanze
concrete (quelle le produce L2.2) né il contenuto (FORGE). Principio cardine: **non tutte le
forme sono pesanti** — principio/stile/skill sono leggere, reparto/ecosistema pesanti. La scelta
dello schema giusto si fa con ingegno, mai meccanicamente.

## Team (agenti)
| id | ruolo | tier |
|---|---|---|
| `arch-schema-keeper` | Custode Schemi Canonici: mantiene/versiona i 9 schemi, serve quello giusto | sonnet |
| `arch-director` | conductor: approva l'evoluzione di uno schema (WF-SCHEMA-EVOLVE) | opus |

## Workflow di competenza
- **Nodo "carica schema" di WF-ARCH-DESIGN** — data la forma classificata da L2.1, serve lo
  schema canonico corretto a L2.2.
- **WF-SCHEMA-EVOLVE (non bloccante)** — quando un artefatto reale rivela un buco nello schema,
  lo schema si aggiorna con versione + diff. La costituzione migliora, non è una gabbia.

## Funzioni
1. **Libreria delle 9 forme** — possiede lo schema-template di ciascuna (tabella sotto).
2. **Selezione FORMA GIUSTA** — date forma+scopo, decide se è leggera o pesante (anti-spreco).
3. **Versioning** — ogni schema ha versione; le modifiche sono diff tracciati, mai overwrite muto.
4. **Estensione con ingegno** — se serve una forma nuova, ne progetta lo schema e lo aggiunge.
5. **Fonte di verità per il gate** — L2.4 misura "completo/incompleto" contro questi schemi.

**Le 9 forme e il peso dello schema:**
| Forma | Peso | Lo schema possiede… |
|---|---|---|
| Skill | media | SKILL.md (frontmatter+kernel ≤500 righe), references/, progressive disclosure, evals |
| Agente | media | identità, missione, I/O concreto, tool, logica, escalation, KPI (7-file) |
| Team | pesante | coordinator+workers, handoff contract, shared_state, acceptance, failure handling |
| Principio | **leggera** | enunciato, perché, quando si applica, test di rispetto, esempi/anti-esempi |
| Stile | **leggera** | regole visive/voce, do/don't, token/pattern, esempi conformi e non |
| Workflow | media | trigger, input, pipeline a passi, gate, output, owner, dry-run |
| Documento/MKD | media | struttura, atomi informativi, cross-ref, mai riassunto (sempre espansione) |
| Reparto | pesante | missione, team L3/L4, workflow, handoff, gate, KPI |
| Ecosistema | **pesante** | org L1→L5, BACKBONE, namespace memoria, dossier, handoff inter-eco |

## Handoff Contract (Input → Output → Gate)
- **Input:** `{ forma, scopo }` classificati da L2.1.
- **Output:** `schema_canonico = { forma, peso, sezioni_obbligatorie[], io_atteso{}, versione }`
  servito a L2.2 e a L2.4.
- **Gate:** la forma è coperta da uno schema esistente (altrimenti apre WF-SCHEMA-EVOLVE prima
  di servire); il peso scelto è proporzionato (no schema pesante per forma leggera).

## Flusso interno (passi reali)
```
{forma, scopo} da L2.1
  → arch-schema-keeper: la forma è nella libreria delle 9? 
       sì → carica schema versione corrente
       no → WF-SCHEMA-EVOLVE: progetta nuovo schema → arch-director approva → versiona
  → arch-schema-keeper: verifica peso proporzionato (leggera vs pesante, anti-spreco)
  → serve schema a L2.2 (per istanziare) e a L2.4 (come riferimento del gate)
  ── feedback loop: L2.4/RETRO rivela buco ricorrente → WF-SCHEMA-EVOLVE → nuova versione +diff
Output: schema_canonico versionato → architettura/schemi/<forma>@<versione>
```

## shared_state / memoria (namespace architettura/...)
- `architettura/schemi/<forma>@<versione>` — i 9 schemi canonici versionati (fonte di verità).
- `architettura/schemi/_changelog` — diff di ogni evoluzione schema (WF-SCHEMA-EVOLVE).
- `patterns` (ReasoningBank, relay) — buchi strutturali ricorrenti che rafforzano gli schemi.
- Motore reale: `skill-creator` (schema skill), `architect-agent` (schema agente), `org-design`
  (schema reparto/ecosistema), `content-forge` (schema MKD).

## Gate / KPI
| KPI | Target |
|---|---|
| Forme con schema canonico presente e versionato | 9/9 |
| Peso schema proporzionato alla forma (no over-engineering) | 100% |
| Evoluzioni schema con diff tracciato (mai overwrite muto) | 100% |
| Buchi ricorrenti distillati in evoluzione schema entro 1 RETRO | trend ↑ |
