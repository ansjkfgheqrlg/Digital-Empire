# L2.5 — PROGETTAZIONE ECOSISTEMI
## Organo: ARCHITETTURA (Genesi Core)

## Missione
È il **livello di design più grande**: disegna **org chart interi L1→L5** — ecosistemi completi
con reparti, team, BACKBONE, namespace memoria e bozza dossier — che poi la FORGE popola.
Confine netto: L2.5 progetta lo *scheletro organizzativo* di un organo intero (chi-fa-cosa,
gerarchia, handoff inter-reparto), NON il contenuto dei singoli agenti/skill (FORGE) né il
mandato strategico (Board/MAXIMILIAN). È come ARCHITETTURA progetta gli organi della holding.

## Team (agenti)
| id | ruolo | tier |
|---|---|---|
| `arch-org-designer` | Progettista Ecosistemi: disegna org L1→L5 interi (reparti/team/handoff) | opus |
| `arch-blueprint` | (da L2.2) disegna la struttura millimetrica dei singoli nodi dell'org | opus |
| `arch-director` | conductor: riceve il mandato del Board, consegna l'org alla FORGE | opus |

## Workflow di competenza
- **WF-ECOSYSTEM-DESIGN** (il livello massimo) — dato un mandato del Board ("serve l'ecosistema
  E-commerce"), produce org L1→L5 + BACKBONE + namespace + bozza dossier → handoff alla FORGE
  (WF-ECOSYSTEM-NEW) per la costruzione.
- Usa lo schema canonico **Ecosistema** (forma pesante, L2.3) come riferimento di completezza.

## Funzioni
1. **Org chart L1→L5** — Direttore (L1) → reparti (L2) → team (L3) → workers (L4) → agenti (L5).
2. **Confini dei reparti** — missione netta per ciascuno, zero sovrapposizioni (anti-collisione).
3. **Handoff inter-reparto** — chi passa cosa a chi, con quale contract e gate.
4. **BACKBONE** — l'infrastruttura condivisa (memoria, namespace, tool) dell'ecosistema.
5. **Namespace memoria** — lo schema `<eco>/...` per shared_state e recall semantico.
6. **Bozza dossier** — il documento-madre che la FORGE espanderà (mai partire da zero alla cieca).

## Handoff Contract (Input → Output → Gate)
- **Input:** `mandato = { ecosistema, scopo, perimetro }` dal Board (via `arch-director`).
- **Output:** `org_design = { org_L1_L5{}, reparti[], handoff_inter_reparto[], backbone{},
  namespace[], bozza_dossier }` in `architettura/blueprint/<eco>/org`.
- **Gate:** ogni reparto ha missione+confine netto (0 sovrapposizioni), org coperta L1→L5,
  handoff inter-reparto definiti, BACKBONE+namespace presenti → validato da L2.4 prima di FORGE.

## Flusso interno (passi reali)
```
mandato Board {ecosistema, scopo, perimetro}
  → arch-org-designer: scompone lo scopo in reparti L2 con confini netti (anti-overlap)
  → arch-org-designer: per ogni reparto → team L3/L4 + roster agenti L5
  → arch-blueprint (per nodo): struttura millimetrica del singolo reparto/team
  → arch-org-designer: handoff inter-reparto + BACKBONE + namespace + bozza dossier
  → arch-validator (L2.4): org completa L1→L5? confini netti? handoff definiti? → gate
  → arch-director: PASS → HANDOFF a FORGE (WF-ECOSYSTEM-NEW costruisce il contenuto)
Output: org_design L1→L5 validato → architettura/blueprint/<eco>/org
```

## shared_state / memoria (namespace architettura/...)
- `architettura/blueprint/<eco>/org` — l'org-design completo di ogni ecosistema, a freddo.
- `architettura/schemi/ecosistema` (lettura) — schema canonico forma Ecosistema (riferimento).
- `architettura/pattern` (lettura) — pattern org riusabili (es. coordinator+workers, gate-in-serie).
- Motore reale: `org-design` + `ecosystem-scaffold` (da forgiare) + benchmark org reali (10 eco).

## Gate / KPI
| KPI | Target |
|---|---|
| Org coperta a tutti i livelli L1→L5 | 100% |
| Reparti con missione+confine netto, 0 sovrapposizioni | 0 overlap |
| Handoff inter-reparto definiti con contract | 100% |
| BACKBONE + namespace memoria presenti nell'org-design | 100% |
| Org-design che superano il struct-gate (L2.4) prima della FORGE | 100% |
