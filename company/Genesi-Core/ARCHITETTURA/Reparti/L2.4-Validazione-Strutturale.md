# L2.4 — VALIDAZIONE STRUTTURALE
## Organo: ARCHITETTURA (Genesi Core)

## Missione
È il **gate strutturale deterministico** della holding (`struct-gate`): prende un artefatto
(blueprint o artefatto costruito) e dice **COMPLETO / INCOMPLETO** con la lista esatta dei buchi
rispetto allo schema canonico. Verifica anche che il nuovo artefatto non **collida/contraddica**
l'esistente. Confine netto: L2.4 giudica la *completezza strutturale* — NON se "è all'altezza di
Max" (MAXIMILIAN) né se è *lecito* (Mandato). Due gate diversi, in serie, dopo questo.

## Team (agenti)
| id | ruolo | tier |
|---|---|---|
| `arch-validator` | Validatore Strutturale: gate `struct-gate`, completo/incompleto + buchi esatti | sonnet |
| `arch-contradiction` | Anti-Contraddizione: il nuovo artefatto si sovrappone/contraddice l'esistente? | sonnet |
| `arch-director` | conductor: riceve l'esito gate, blocca o autorizza l'handoff a FORGE | opus |

## Workflow di competenza
- **WF-STRUCT-VALIDATE** (il gate riusabile) — usato **due volte**: *pre-FORGE* (il blueprint è
  completo?) e *post-FORGE* (l'artefatto costruito rispetta il blueprint?).
- **Nodo GATE di WF-ARCH-DESIGN** — blocco duro: blueprint non validato → niente FORGE.
- Alimenta il passo 4 (GATE) del ciclo a 9 passi come gate automatico.

## Funzioni
1. **Diff vs schema canonico** — confronta artefatto ↔ `sezioni_obbligatorie` dello schema (L2.3).
2. **Lista buchi esatta** — non "manca qualcosa", ma *quale* sezione/campo/handoff manca, dove.
3. **Determinismo** — stesso input → stesso esito; il gate è eseguibile, non opinione.
4. **Anti-contraddizione** — `arch-contradiction` cerca artefatti esistenti che si sovrappongono
   o confliggono (stesso scopo, naming collidente, regole opposte).
5. **Esito bloccante** — INCOMPLETO o COLLISIONE → rimanda a L2.2 (blueprint) o L2.1 (spec).
6. **Doppio passaggio** — registra esito pre e post FORGE per provare che il costruito = disegnato.

## Handoff Contract (Input → Output → Gate)
- **Input:** `artefatto` (blueprint o costruito) + `schema_canonico` (L2.3) + `acceptance` (L2.1).
- **Output:** `validazione = { esito: COMPLETO|INCOMPLETO, buchi:[{sezione, cosa_manca}],
  collisioni:[{con_chi, tipo}], fase: pre|post }` in `architettura/validazioni/<id>`.
- **Gate:** esito `COMPLETO` + 0 collisioni bloccanti → autorizza handoff a FORGE; altrimenti
  blocca e rimanda con la lista buchi (regola di blocco dossier §4: niente costruzione al buio).

## Flusso interno (passi reali)
```
artefatto (blueprint pre-FORGE, o artefatto costruito post-FORGE)
  → arch-validator: carica schema_canonico (L2.3) della forma
  → arch-validator: diff sezioni_obbligatorie ↔ artefatto → lista buchi puntuale
  → arch-contradiction (parallelo): skill-contradiction-analyzer → sovrapposizioni/conflitti?
  → buchi vuoti AND collisioni vuote ? → esito COMPLETO : → esito INCOMPLETO/COLLISIONE
  → arch-director: COMPLETO → autorizza HANDOFF a FORGE (pre) / chiude design (post)
                   altrimenti → rimanda a L2.2 (struttura) o L2.1 (spec) con i buchi
Output: validazione {esito, buchi, collisioni, fase} → architettura/validazioni/<id>
```

## shared_state / memoria (namespace architettura/...)
- `architettura/validazioni/<id>` — esiti struct-gate (pre+post), ricostruibili a freddo.
- `architettura/schemi` (lettura) — riferimento contro cui si misura la completezza.
- `architettura/blueprint/<id>` (lettura) — l'artefatto sotto esame.
- `patterns` (relay) — i buchi ricorrenti ("dimenticano sempre l'escalation") → ReasoningBank → L2.3.
- Motore reale: `skill-contradiction-analyzer`, `agent-quality-sentinel`, `verification-quality`.

## Gate / KPI
| KPI | Target |
