# CP-20260909-6R2M — /frantuma: l'ID in fase 2 e' il percorso vero del file, non una frase

- **Data:** 2026-09-09
- **Ecosistema/Reparto:** 10-MEMORY / auto-implementazione di Emperator
- **Task:** durante una prova a vuoto (Max: "facciamo una prova ora... fingi") il finto output
  di FASE 2 mostrava la frase "ID ufficiale, usabile in altre chat/sessioni" letterale su ogni
  riga. Max: *"lo sai che 'ID ufficiale, usabile in altre chat/sessioni' quando lo fai devi
  mettere un ID vero? ora inventalo."*
- **Esito:** ✅ corretto. Un ID non e' una frase rassicurante: e' qualcosa che si apre. `report()`
  ora stampa il **percorso reale del file coniato**
  (`company/Memory/tasks/micro/<PADRE>/MT-0N-<slug>.md`) al posto della frase generica — quello
  e' l'ID vero, cio' che un'altra chat/sessione apre per eseguire la micro-task.
- **Output:** `scripts/frantuma.py` (`leggi_tutte` ora porta anche `percorso`, `report` lo
  stampa), `tests/test_frantuma.py` aggiornato, `emperator.md` §6.24 corretta.
- **Decisioni prese:** nessuna ADR.
- **Lezioni/errori:**
  - **Una frase che descrive una proprietà ("è ufficiale") non è la proprietà stessa.** Il test
    dell'utilità di un ID è "posso aprirlo?" — se la risposta è no, non è un ID, è un'etichetta.
    Lo stesso errore di fondo dei "PASS finti" già visto altrove nel repo (push_social.py,
    main_orchestrator.py): un segnale che sembra dire la cosa giusta senza portare il dato che
    la renderebbe vera.
  - **La prova a vuoto ("fingi") ha comunque trovato un difetto reale**, perché il difetto era
    nello schema stesso, non nei dati: si sarebbe visto identico anche in un conio vero.
- **Costi:** nessuna chiamata a modello.
- **Prossimo passo:** nessuno aperto su questo filone — la funzione e' ora completa: due fasi,
  schema fisso, colore viola, ID vero (percorso) in fase 2.
