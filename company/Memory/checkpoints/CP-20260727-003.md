  ufficiale di orchestrazione) era rotto (`ModuleNotFoundError: agente_scraper`) perché la Phase A
  (25/07, commit `bcd4ef89`) aveva cancellato gli 8 agenti flat di `03-AGENTI-E-RUOLI/` per il

- **Esito:** ✅ completato — Phase B chiusa, import puliti, 13/13 test verdi.

## Cosa è stato fatto
1. **Recuperato il contenuto originale** degli 8 file flat cancellati via
   `git show bcd4ef89~1:<path>` (nessuna riscrittura da zero — logica portata, non reinventata).
2. **Ricostruiti 6 agenti per porting diretto** nel pattern cartella-per-agente (stessa struttura
   di `writer/`: `<nome>/agente.py` + `<nome>/AGENTE.md`): `scraper/`, `qualificatore/`, `sender/`,
   `responder/`, `integratore-sheets/`. Logica invariata rispetto ai file flat originali.
3. **`gate/` ricostruito per delega, non per porting**: il vecchio `agente_gate.py` cancellato
   duplicava già ~200 righe di logica presenti in `02-AUTOMAZIONI-E-SCRIPTS/gate_agent.py`.
   Portarlo verbatim avrebbe reintrodotto la duplicazione che il docstring di `agents.py` vieta
   esplicitamente ("NON duplicare logica qui"). `gate/agente.py` ora **estende**
   `gate_agent.GateAgent`, aggiungendo solo caricamento di `AGENTE.md` e CLI.
4. **`orchestratore/` ricostruito per alias, non per porting**: il vecchio
   `agente_orchestratore.py` (252 righe, Phase 3 del 25/07) duplicava quasi integralmente
   `02-AUTOMAZIONI-E-SCRIPTS/orchestrator.py` (stessa inizializzazione EventBus/Memory/Gate/
   MetaOptimizer, stesso ciclo Playwright, stessi argomenti CLI). `orchestratore/agente.py` ora
   espone solo `OrchestratorAgent = Conductor` (da `agents.py`) e rimanda a `orchestrator.py`
   come unico entry point CLI reale.
5. **Riparata la facade `agents.py`**: le 7 classi si caricano ora via
   `importlib.util.spec_from_file_location` con nomi modulo univoci (`agente_scraper`,
   `agente_qualificatore`, ecc.), necessario perché ogni cartella contiene un file chiamato
   identicamente `agente.py` — un `import` posizionale semplice avrebbe causato collisioni in
   `sys.modules` (solo il primo `agente.py` caricato sarebbe stato effettivamente usato).
6. **Verificato**: `python -c "import agents"` pulito, `python -m unittest test_apex7 -v` →
   **13/13 PASS**, `orchestrator.py`/`run.py` sintassi valida (import indiretto via `agents`,
   non toccano `03-AGENTI-E-RUOLI` direttamente — nessuna modifica necessaria lì).
7. **Sync concorrente gestito**: durante il lavoro, un processo di auto-sync ha committato in
   autonomia 5 delle 7 cartelle (`scraper/qualificatore/sender/responder/integratore-sheets`) e
   il repo era andato 2 commit indietro rispetto a `origin/main` (lavoro parallelo non correlato:
   PEZZO 2 agenti operativi, CRO-copy-architect). Risolto con `git stash push -u` → `git pull
   --ff-only` → `git stash pop`, zero conflitti.

## Decisioni prese
- **Non tutti i 7 agenti si ricostruiscono allo stesso modo**: dove il file cancellato duplicava
  già logica altrove (gate, orchestratore), la ricostruzione corretta è delegare/aliasare, non
  copiare — copiare avrebbe *reintrodotto* il problema che il pattern cartella-per-agente doveva
  risolvere. Dove non c'era duplicazione pre-esistente (scraper/qualificatore/sender/responder/
  sheets), il porting diretto è la scelta giusta (nessuna logica da consolidare).

## Lezioni
- Un "Phase A: wipe, pronto per rebuild" senza il rebuild immediato lascia la facade rotta per
  giorni se nessuno verifica a runtime (`python -c "import agents"` non è mai stato eseguito tra
  la Phase A del 25/07 e questa sessione). Vale la stessa lezione di [[CP-20260727-001]]: uno
  stato "intermedio" non è mai gratuito, va sempre chiuso o segnalato esplicitamente come bloccante.
- Recuperare da `git show <commit>~1:<path>` invece di riscrivere a memoria ha permesso di
  preservare al 100% la logica originale (rate limit sender, hook selection writer, criteri
  Data-Validator-Gate) — coerente col vincolo additivo generale del progetto.
