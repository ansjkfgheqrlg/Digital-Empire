## 3. Bug trovato e corretto durante la chiusura (non previsto dal gate, ma reale)
Verificando `git status` prima del commit finale è emerso che `test_apex7_orchestrator_e2e`
sovrascriveva silenziosamente la dashboard reale tracciata
(`06-DASHBOARD-E-METRICHE/YOUTUBE-PERFORMANCE-DASHBOARD.md`) con i dati del run di test
(`run_id` tipo `test-yt-...`) ad ogni esecuzione della suite — `write_dashboard()` (TASK-YT-005)
usava `FACTORY_DIR` direttamente invece di un attributo overridabile, a differenza di
`state_file`/`decision_log_path`/`perf_logs_path` ecc. che sono già isolati per i test. Esatto lo
stesso tipo di problema che questo intero task ha passato 5 lotti a eliminare (dati non reali che
finiscono nel percorso di produzione) — corretto: `Apex7Orchestrator.__init__` ora espone
`self.dashboard_path` (default: percorso reale, invariato per l'uso normale),
`write_dashboard()` lo usa invece di ricalcolare il path; `test_youtube_apex7.py` lo sovrascrive
con un path isolato in `test_templates_dir`, come già fa per gli altri file di stato. Verificato:
`git status` sulla dashboard resta pulito dopo `python -m unittest test_youtube_apex7 -v`
(prima del fix mostrava una modifica ad ogni run).
