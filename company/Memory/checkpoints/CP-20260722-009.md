# CP-20260722-009 — G-B chiuso: fix memory_manager.py (crash Unicode Windows)

- **Data:** 2026-07-22
- **Ecosistema/Reparto:** Empire Core Runtime — lotto G-B (Gael), ordine P0 di Max,
  `company/Memory/tasks/TASK-GAEL-20260722-EMPIRE-RUNTIME.md`.
- **Task:** correggere `WORKFLOW-ESTATE/02-AUTOMAZIONI-E-SCRIPTS/memory_manager.py`, che oggi
  crasha su Windows (`UnicodeEncodeError: 'charmap' codec can't encode character '\U0001f9e0'`),
  senza cambiarne l'interfaccia CLI né i formati dei record (ADR-003).

## Esito: ✅ G-B chiuso.

### Diagnosi
Il file usava già `encoding="utf-8"` in ogni `open()`/`read_text()`/`write_text()` (quella parte
era già corretta). Il bug reale è nei `print()` con emoji (`✅`, `🧠`, `📊`, `🔎`): sulla console
Windows nativa (cp1252) `sys.stdout` non riesce a codificarle e solleva l'eccezione. `ROOT` era
già risolto via `Path(__file__).resolve().parent` (indipendente dal CWD di per sé), ma non passava
per `empire.paths` come richiesto dal brief (fondazione unica dei path).

### Fix applicato (minimo, non invasivo)
In testa al file, prima di qualunque `print()`:
- risale l'albero da `__file__` cercando `company/Mandato/MANDATO-EMPIRE.md`, aggiunge la radice a
  `sys.path`, importa `empire.paths.safe_stdout` + `empire.paths.resolve` e li usa
  (`ROOT = resolve("wf_scripts")`).
- **fallback silenzioso**: se `empire/` non è raggiungibile per qualunque motivo, ripristina il
  comportamento originale (`reconfigure(encoding="utf-8", errors="replace")` inline +
  `ROOT = Path(__file__).resolve().parent`) — lo script resta autonomo come prima, non dipende
  in modo fragile da `empire/`.
- **Zero righe toccate** in argparse, nei nomi dei comandi, nei formati degli atomi (`atom()`,
  `add_index()`, header YAML) — verificato con un comando di scrittura reale (`metric`), poi
  ripulito l'artefatto di test.
