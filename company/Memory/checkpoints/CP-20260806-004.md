## CP7 — Cover Generator
`_build_cover_prompt()` costruisce il prompt dai dettagli REALI del libro (titolo, genere/
keyword, personaggi, trama — presi da research+planning, non solo il titolo), mai un prompt
fisso copiato da un altro libro — lo stesso bug di fondo dell'audit originale
(`genera_nuovo_libro.py` copiava sempre lo stesso file .png a prescindere dal libro).
`generate_cover()` riusa `lmarena_client.send_image_prompt` (CP4, gia' verificato in
produzione con screenshot reale). Self-test genera 2 copertine per 2 libri deliberatamente
molto diversi (cozy mystery vs thriller post-apocalittico) e verifica che le dimensioni file
siano DIVERSE — stesso test forense gia' usato in CP2/CP8 per smascherare il bug
copia-template dell'audit originale.

## CP9 — tutte le fasi collegate
Aggiunte `make_real_planning_dep()` e `make_real_writing_dep(total_chapters, words_per_chapter)`
in `orchestrator.py`, stesso schema di `make_real_research_dep`: ognuna apre/chiude una
propria sessione LM Arena indipendente — non condivisa fra fasi, cosi' un resume dopo crash
puo' rilanciare una fase da sola in un processo diverso senza bisogno di un browser gia'
aperto in memoria di un processo precedente (motivazione tecnica, non solo stilistica: il
meccanismo di resume di CP9 e' progettato apposta per processi diversi). `_phase_cover` ora
passa il contesto completo (research+planning+writing) alla dependency cover invece del solo
titolo. Default 24 capitoli x 1500 parole = 36000, dentro il range target di
`kdp_formatter` (120±5 pagine a 300 parole/pagina = 34500-37500).

**Bug reale corretto nello stesso commit**: gli errori reali (NO-GO qualifica, formattazione
fuori target, sessione LM Arena non valida) uscivano con `exit(0)` nella CLI, stessa uscita
usata per gli stop onesti attesi (fase non ancora costruita) — un run fallito sarebbe
sembrato riuscito a chiunque controllasse solo l'exit code. Separato: `NotImplementedError`
→ `exit(0)` (atteso), qualunque altro `RuntimeError` → `exit(1)` (fallimento reale).
