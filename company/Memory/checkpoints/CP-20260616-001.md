# CP-20260616-001 — Fix collisione case-insensitive in 06-PLATFORM/Reparti

## Problema trovato

5 file in `company/Ecosistemi/06-PLATFORM/Reparti/` erano tracciati da git con
**doppia grafia** (collisione case-insensitive su Windows, `core.ignorecase=true`):

| Fantasma MAIUSCOLO (rimosso) | File reale Title-Case (tenuto) |
|---|---|
| DEPLOY-CICD.md | Deploy-CICD.md |
| PRODUCT-ENGINEERING.md | Product-Engineering.md |
| SECURITY-QUALITY.md | Security-Quality.md |
| TOOLING-AUTOMATION.md | Tooling-Automation.md |
| WEB-ENGINEERING.md | Web-Engineering.md |

**Causa:** lo swarm notturno F1-bis (11/06) creò i file in MAIUSCOLO; un giro successivo
li ricreò in Title-Case. Su filesystem case-insensitive esiste UN solo file fisico per
coppia, ma git aveva 2 voci d'indice → `git status` mostrava "modified", `git add`/`commit`
non riuscivano a stagiare nulla. Il doppione era già stato pushato → presente anche nel
remoto (quindi sul PC di Max).

## Fix applicato (non distruttivo)

1. Backup contenuto dei 5 file su `%TEMP%\platform-reparti-backup-20260616`.
2. Rimozione SOLO delle 5 voci fantasma MAIUSCOLO dall'indice con
   `git -c core.ignorecase=false rm --cached <PATH-MAIUSCOLO>` (disco mai toccato).
3. `git add` dei 5 file Title-Case reali → indice pulito, 1 voce per file.
4. Commit `f1d0457` + push.

## Esito

- Working tree pulito; **0 collisioni** residue (`git ls-files` group-by lower = 0 duplicati).
- Contenuto arricchito (header `> Fonte:` + schede L2 estese) PRESERVATO nei Title-Case.
- Allineato con origin.

## Lezione (per ReasoningBank / prompt swarm futuri)

Gli agenti swarm su Windows devono usare una **convenzione di naming fissa** per i file
(decidere Title-Case O MAIUSCOLO, mai mischiare) altrimenti generano collisioni
case-insensitive che bloccano i commit. Da aggiungere come regola nei prompt swarm F1-bis/V2.
