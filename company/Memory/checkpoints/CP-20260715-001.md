# CP-20260715-001 — Max — PreventivoForge: GUI premium senza WebView2 (motore Chrome-app)

**Data:** 2026-07-15

## Problema (ricorrente, grave)
Novacar riceveva l'app e la GUI era la VECCHIA (Tkinter): niente Archivio, header chiaro.
"Funziona" (genera PDF) ma grafica sbagliata. Max rimandava il file → stesso risultato.

## Causa radice (E11)
La GUI premium (pywebview) su Windows usa il backend **EdgeChromium/WebView2**, che richiede il
**WebView2 Runtime** installato sul PC. Sul PC di Max c'è → premium. Sul PC di Novacar mancava →
pywebview alza eccezione → `app.py` ripiegava **in silenzio** su Tkinter (GUI vecchia).
**Non riproducibile da Max** (sul suo PC WebView2 c'è) → ogni fix precedente era al buio (incluso il
bootstrapper WebView2 di E10, che poteva comunque fallire l'install sul PC cliente).

## Soluzione (definitiva, testabile)
Nuovo motore GUI **`main_chrome_app()`** in `app.py`:
- la stessa `ui/index.html` premium è servita da un **mini-server locale** (`http.server` su 127.0.0.1);
- resa in una finestra **Google Chrome `--app`** (senza barre) — Chrome è GIÀ richiesto (scraping+PDF) → sempre presente;
- bridge JS↔Python via `POST /api/<metodo>` (dealers/generate/poll/archive/open_pdf) — riusa `_WebApi`;
- shim JS iniettato a runtime (`window.pywebview.api.*` → fetch) → `ui/index.html` **invariata su disco**.
- ordine motori in entry point: **Chrome-app → pywebview → Tkinter** (+ scrive `AVVIO-DIAGNOSTICA.txt` sui fallimenti).
- **Zero dipendenza WebView2.** "Quel che vede Max = quel che vede il cliente."

## Verificato

- **Deliverable estratto come Novacar** (`Expand-Archive` → avvio quell'exe): premium OK.
